# 核心论述：升维路径

**D 数字结果 → C 数据解读 → B 分析判断 → A 业务结论**  
数字本身不是答案，数字放回分析框架内得出的判断才是答案。

## 核心论断（≤5 条）

1. **做减法而非叙事**：从几十个数字中划掉绝大多数，只留 3-5 个真正值得关注的。挑得准是分析师能力的关键划分线。

2. **异动即信号，而非噪音**：AI 最容易的错误是把每个数字念一遍。真正的信号是：做减法后剩下的，且有明确基准的那些。

3. **归因而非描述**：从“哪个数有问题”升级到“为什么有问题”。缺少因果链条的归因是无效的。

4. **两种归因模式**：
   - **异步场景**：假设-验证循环（取数验证 → 排除混淆 → 留证据 → 迭代），适合深度归因
   - **即时问答**：指标关系 → 公式拆解 → 维度贡献分解，快速定位大头

5. **业务知识的可复制性**：将“手感”拆解为：
   - 指标公式与关系图
   - 构成模型（加法/乘法/除法分解）
   - 外部事件库（节日、竞品、政策、天气等）
   - 内部动作记录（活动、产品发版、算法变更）

## 第一性原理（First-principles reduction）

- **数据噪音 vs 信号**：分析师角色是筛选噪音的过滤器
- **上下文决定含义**：数字无内在含义，含义来源于业务框架
- **归因而非描述**：描述问题 ≠ 解决问题
- **可复制性的关键**：将不可复制的“手感”转化为可执行的模型

## 实践推论（Chinese tech audience）

- **报告结构**：不再是“一屏平铺的数字”，而是“有基准的关键信号 + 异常程度 + 归因判断”
- **Agent 建设**：
  - 建设**指标知识库**（定义、公式、边界）
  - 建设**模型库**（统计检验、差分法、贡献度分解）
  - 建设**外部事件采集系统**（节日、竞品动作等）
  - 固化**判断方式**而非自由探索
- **避坑**：避免“复读机”模式（念完每个数字却找不到问题重点）

## 原文明细（关键保留）

- **第四步（D→C）**：做减法、识别重点、异动判断方法、Agent 需要建设什么
- **第五步（C→B）**：归因的难点、横向比+往下钓、排除混淆、两种可执行模式、Agent 需要建设什么
- **关键句**：“会念数字的是复读机，会挑重点、给基准才是分析师。”
- **补知识**：分析方法库（加法/乘法/除法模型、差分法、LMDI 对数分解）、外部事件采集系统
